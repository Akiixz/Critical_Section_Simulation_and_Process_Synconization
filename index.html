Critical Section & Process Synchronization

จำลองปัญหา Race Condition และวิธีแก้ด้วย Mutex Lock / Semaphore แบบ เทียบสองฝั่งพร้อมกัน — ใช้ async/await แทรกจุดสลับงาน (yield point) เพื่อเลียนแบบการสลับ thread ของจริง ปรับความเร็วหรือกดหยุดชั่วคราวเพื่ออธิบายทีละขั้นได้

วิธีอ่านภาพ (กดเพื่อซ่อน/แสดง)
  • ทุก Thread วนทำงาน 3 ขั้น: READ (อ่านค่า Counter เก็บไว้ใน reg ของตัวเอง) → +1 (คำนวณ) → WRITE (เขียนค่ากลับเข้า Counter)
  • ลูกกลมสีน้ำเงิน = ค่าที่ อ่าน ออกมา · ลูกกลมสีเขียว = ค่าที่ เขียน กลับไป
  • ถ้า Thread เขียนทับค่าที่คนอื่นเพิ่งแก้ → Counter กระพริบ แดง และมีเลข −N ลอยขึ้น = Lost Update
  • แถบ Timeline ด้านล่าง: ช่องสีส้ม = อยู่ใน Critical Section · แถบแดงโปร่งใส = มีหลาย Thread อยู่ใน CS พร้อมกัน (สิ่งที่ห้ามเกิด) · ฝั่งที่มี Lock จะเรียงต่อกันทีละคน
  • เปรียบเทียบ เวลาที่ใช้ ของสองฝั่งด้วย — ฝั่งที่มี Lock ถูกต้องแต่ช้ากว่า (Trade-off)

วิธีอ่านภาพ (กดเพื่อซ่อน/แสดง)
  • 🥐 บินจาก Producer (ด้านบน) ลงไปวางในช่องของ ถาด / Buffer แล้ว Consumer (ด้านล่าง) มาหยิบไป
  • empty = จำนวนที่ว่างเหลือในถาด · full = จำนวนของที่พร้อมให้หยิบ — สองตัวนี้คือ Semaphore · mutex = กุญแจให้เข้าแตะถาดได้ทีละ 1 คน
  • การ์ดกะพริบแดง ⏸ = กำลัง รอ (ถาดเต็มหรือว่าง) — ฝั่งที่มี Semaphore เป็นพฤติกรรมที่ถูกต้อง
  • ช่องแดงเส้นประ = Overflow (ของล้นถาด) · การ์ด Consumer สั่นแดง = Underflow (หยิบจากถาดว่าง หรือโดนคนอื่นหยิบตัดหน้า)
